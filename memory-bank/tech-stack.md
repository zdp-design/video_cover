# 短视频封面制作工具技术栈推荐

## 1. 选型原则

- **简单优先**：能少一层抽象就少一层
- **健壮优先**：优先选择成熟生态、长期维护的库
- **本地优先**：编辑与导出不依赖后端
- **可扩展**：后续可平滑增加模板市场、批量生成等能力

## 2. 推荐技术栈（最合适方案）

### 2.1 前端基础

- **React 18 + TypeScript**
- 原因：
  - 社区最大、资料最全，招聘和维护成本最低
  - TypeScript 可显著降低编辑器业务中的状态与数据错误

### 2.2 构建工具

- **Vite**
- 原因：
  - 启动快、构建配置简单
  - 适合中小型前端工具类项目，默认体验稳定

### 2.3 画布编辑引擎

- **Konva + react-konva**
- 原因：
  - 对“拖拽、缩放、旋转、层级、选中框”支持成熟
  - React 集成自然，业务代码更直观
  - 相比自研 Canvas 逻辑，复杂度和 bug 风险大幅下降

### 2.4 状态管理

- **Zustand**
- 原因：
  - API 简单，心智负担小
  - 对编辑器状态（当前选中元素、历史记录、模板数据）足够好用
  - 比重型方案更轻，维护成本更低

### 2.5 UI 组件与样式

- **Ant Design + Tailwind CSS（可选）**
- 推荐搭配：
  - 组件层：Ant Design（表单、弹窗、抽屉、下拉等）
  - 布局与细节：Tailwind（快速排版）
- 说明：
  - 若团队偏“统一视觉+少写 CSS”，只用 Ant Design 也完全可行

### 2.6 本地存储

- **IndexedDB（通过 idb 封装库）**
- 用途：
  - 存草稿、用户模板、最近项目
- 原因：
  - 容量和稳定性优于 localStorage
  - 适合存储较大 JSON 与图片元信息

### 2.7 导出能力

- **原生 Canvas API：`toBlob` / `toDataURL`**
- 文件下载：**FileSaver.js（可选）**
- 原因：
  - 能力稳定、依赖少
  - 满足 PNG/JPEG 本地保存需求

### 2.8 测试与质量保障

- 单元/组件测试：**Vitest + React Testing Library**
- E2E：**Playwright**
- 代码规范：**ESLint + Prettier**
- Git 钩子：**Husky + lint-staged**
- 原因：
  - 这套组合是当前前端主流、学习和维护成本最低的稳健方案

## 3. 为什么这套是“最简单但最健壮”

- 不引入后端，减少部署和数据一致性复杂度
- 不自研画布底层，避免高风险图形交互 bug
- 选用主流稳定工具链，出现问题容易定位和搜索解决方案
- 代码结构清晰，后续接入模板市场或 AI 文案功能也不需要推倒重来

## 4. 不推荐的方案（当前阶段）

- 直接自研 Canvas 编辑内核：复杂且维护风险高
- 上来就用微前端/重工程化架构：超出业务体量
- 过度依赖冷门库：长期维护不确定

## 5. 建议版本（示例）

- React `18.x`
- TypeScript `5.x`
- Vite `5.x`
- Konva `9.x` + react-konva `18.x`
- Zustand `4.x/5.x`
- Ant Design `5.x`
- Vitest `2.x`
- Playwright `1.x`

> 版本号以项目初始化当日的稳定版本为准，优先选择非实验版与社区主流版本。
